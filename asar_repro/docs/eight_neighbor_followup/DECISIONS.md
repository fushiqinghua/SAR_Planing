# 本批判断、后端选择与停止规则

交付状态：**`not_run`**。本文件预声明新批规则，不更改上一批 B5、B30 的判定。

## 1. 正确性先于性能

以下任一情况发生时停止后续正式步骤：源码／输入／环境指纹不一致，测试失败、跳过或无实际测试，配对审计不一致或未完成，轨迹非法、漏观测或实际时长不符，评分重放不一致，记录缺失／重复／损坏，异常被初始路线掩盖，forcing 来源或覆盖不满足。

P0 的共同前缀审计用于发现转移、覆盖、概率、几何和引导次序的差异；它与搜索循环 AST 结构约束一起提供有限实现等价性证据。它不证明加速、不证明任意输入上的形式等价，也不证明真实场景最优。

达到预定墙钟或 OPEN 上限，并保存预算内有效路线，是正常资源停止。进程被 watchdog 杀死、求解错误、无预算内可行路线是无效运行；不得用正常资源停止的名称掩盖后者。

## 2. D5 的分组与质量核验

D5 完整矩阵为 48 项。分组 g=(场景,覆盖,邻接)，共有 8 组，每组原／加速各 3 次。先分别计算每个后端的 J 中位数。

质量保护条件：所有 8 组，加速后端的 J 中位数都不得高于原后端中位数超过配置固定的数值容差。这个条件用于避免用速度换掉当前同预算质量，不以某一组的较大改善抵消另一组退化。

报告各次 J、Pd、路径和停止原因，以及展开、生成、终点候选、缓存计数、预处理、引导、转移、重放、算法 wall／CPU、进程 wall 和采样 RSS。较高的展开数或缓存命中率不自动构成质量或达到目标的速度胜出。

## 3. 达到目标的证据

三组固定目标只应用于开发档案的八邻接：

| 目标组 | J_target |
|---|---:|
| Lake / heading_square | 16.752262696441605 |
| Lake / axis_square | 16.7169314627584 |
| Hudson / heading_square | 20.317725021888 |

达到目标定义为：某条完整、有效且经过物理重放的 incumbent，在本次 5 秒预算内满足 J≤J_target+τ，τ 为配置的绝对目标容差（1e−8）。时间取第一条满足条件的预算内记录，不取最后一条最佳解的时间。

每个后端在每个目标组的命中数为 0–3。未命中记 `not_reached`／右删失，时间留空；不能把 5 秒填成真实达到时间，也不能对这种替代值计算平均加速比。只有双方三次都达到同一目标的组，才使用两方目标时间中位数比较。

目标取自已经公开的旧结果，因此 D5 是开发性能诊断，不是独立泛化证据。冻结新目标不会追认上一批 B5 通过，旧 B30 的运行也不充当本批原后端对照。

## 4. 锁定 H1 使用的后端

只有 P0 通过且 D5 全部有效完成，才生成选择记录。采用加速候选需要同时满足：

1. 8 个分组的 J 中位数均通过质量保护。
2. 3 个目标组的命中数均不低于本批原后端。
3. 至少一个目标组的命中数严格增加；**或**至少两个目标组双方都 3/3 命中，且加速后端在这些组的目标时间中位数至少缩短 10%。

否则锁定 `original`。这是性能条件未达标的正常选择结果，H30 仍可继续研究运动模型。若 P0 或 D5 证据无效，则没有合法选择，不能把它当作“候选未获采用”继续。

选择文件记录源码、配置、环境、完整 D5 证据及选择理由。随后才生成四个 H1 输入。H1 得分、路线或任何事后观察都不能改变这个选择；修改源码、候选或规则须建立新版本和新结果目录，不能拼接证据。

## 5. S30 与 H30 放行

H1 的四例身份、时间偏移、seed、forcing 来源在配置中预先固定。缺失 forcing、字节不符、时间不包络原生积分尾帧、生成失败都必须保留并阻断；不能换一个更方便或更有利的实例。

每例 S30 采用同一个预声明的四邻接初始化流程，总预算 30 秒。该路线必须合法、完整，且原评分与 axis 物理评分一致；两种物理覆盖的分数和完整路线均保存。四份输入及共同初始化全部完成后再冻结 H30。

H30 的 48 项必须完整有效。任一必要记录缺失或无效时，状态为 `incomplete_or_invalid`，不计算通过结论。可展示已完成的描述性数据，但不能把缺失记作零改善。

## 6. H1 的逐实例收益和有限迁移门槛

对每个预留实例 i 和覆盖 f，先由各自三次计时重复计算：

\[
G_{i,f}=\frac{\operatorname{median}J_{4,i,f}-\operatorname{median}J_{8,i,f}}
{\operatorname{median}J_{4,i,f}}.
\]

G>0 表示八邻接更好。四个实例各算一次 G；不把三次重复当成三个独立实例，也不直接平均不同 K、Δt 的绝对 J 后解释总体检测时间。

主覆盖条件：

1. 全部四个实例 G_heading≥−1e−8。
2. 至少两个实例 G_heading≥0.005，即 J 中位数改善至少 0.5%。

令 W 为达到 0.5% 的主覆盖赢家集合。同预算 axis 敏感性条件：

1. 至少一个 i∈W 满足 G_axis>1e−8。
2. 全部四个实例 G_axis≥−0.005，即最坏退化不超过 0.5%。

所有条件通过，只表示本批四个预留实例中观察到有限迁移信号。0.5% 和 10% 都是本批预声明的工程阈值，不是统计显著性。

## 7. 状态与解释分层

| 证据 | 解释 |
|---|---|
| 正确性、输入或任务不完整 | `incomplete_or_invalid`；先处理证据问题，不评判方向无效 |
| H1 主覆盖未过门槛 | `within_forcing_screen_not_passed`；保留逐例正负值，不挑赢家汇总 |
| H1 主覆盖通过、axis 未过 | `within_forcing_sensor_sensitive`；需区分路线评分差异与搜索发现能力 |
| 主覆盖与axis均通过，两个场景都有主赢家 | `within_forcing_transfer_signal`；仅限同 forcing 预留实例，仍不是独立天气验证 |
| 主覆盖与axis均通过，主赢家只来自一个场景 | `within_forcing_scene_specific_signal`；明确注明是Lake或Hudson场景限定信号 |

按场景另列两个预留实例中达到主门槛的个数：Lake 为 0/1/2，Hudson 为 0/1/2。不能用 Lake 的改善抵消 Hudson 的主覆盖退化。

`sensor_sensitive` 或类似标签只表示本预算下两种覆盖的实验表现不一致，**不能仅由标签断言收益在物理上只能依赖方形旋转**。若后续进行固定路线跨覆盖复算，应标为事后机制诊断，不能替代本批独立搜索、计算预算或预声明判定。

## 8. 后续行动

| 结果 | 后续安排 |
|---|---|
| D5 达到候选采用条件 | 保留该固定加速版本，用锁定后端完成全部 H1 |
| D5 正确但性能未达采用条件 | 保留原后端完成H1；结束本轮缓存开发，不自动开参数搜索 |
| H1 出现场景限定信号 | 先解释该场景的时空结构，下一批保留不利场景而非移除 |
| H1 的两个场景均有信号 | 固定方法，准备需要新 forcing 的 H2；另行声明新日期与预算 |
| H1 没有达到门槛 | 按有限批次结束，分析逐例原因；不自动扩到300秒 |
| 发现语义、时间、概率或来源问题 | 保存失败，修复后新目录、重新验证与冻结 |

H2、真实相机标定、转弯动力学、任意角度规划、跨覆盖候选生成和新的 STDC 下界均不属于本批已启用任务。它们需要根据本批证据另行设计，不能把未运行工作写成结论。
