## 3. 审查期间加强的检查

以下问题在静态审查中提出，并已在交付实现中补充对应检查：

1. **干净工作树中的导入来源。** runner 指定当前 `src`，并检查已加载项目模块的路径，防止误用其他目录的 editable 安装。
2. **阶段完整性与计费闭合。** 从“阶段数量不超过上限”加强为精确阶段序列；检查每槽上限、累计耗时、接纳时刻和最终包装开销。
3. **执行时刻的精确核对。** 将宽松的上下界核验改为原模型下的请求/锚点重建及阶段结束物理推进等式，避免只使用较早的候选验证时刻而漏掉后续计算。
4. **无候选的早期预算停止。** 若内部调用在完成根状态准备之前已合法耗尽预算，允许保留旧路线；不把这个无候选回退误判为前缀被修改。已有新候选或根证据时仍严格要求身份一致。
5. **失败原始信息保留。** worker 出错时保存当时的 raw 结果与错误；非有限诊断值以可保存形式记录，不能因 JSON 写出失败丢掉故障现场。
