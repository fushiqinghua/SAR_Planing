# 精确状态等价合并的判定与停止规则

状态：`prepared_not_run`。这些规则在运行前固定，不预填实验通过结论。

## 1. 实验身份与阶段有效性

新协议以结果提交 `6084c7d6528a863709466e1dfbb0930459d95414` 为父参考，继续使用四个已见 H2 开发实例。C0/C1 的原固定滚动 pilot 结论保留。本轮因用户明确要求深化而引入一个新的、可被证伪的状态合并机制，不回改原判定或原输出。

每阶段首先检查任务完整性、代码／环境／输入／共同路线身份、运行前冻结、预算、原评分一致性、滚动前缀因果性及索引记录。缺失、失败或异常不得删除后以剩余任务汇总为完整结果。

D0 必须四项全部有效；F30 必须 48 项全部有效。F30 还要求完整 D0 原始证据及对应冻结门槛文件一致。D0 的任何候选或缓存不进入正式 F30 初始化。

## 2. D0 机会门槛

对每个实例定义：

\[
R_s=\frac{N_{\mathrm{mergeable},s}}{N_{\mathrm{eligible},s}}.
\]

`N_eligible = nonterminal_children`：主搜索原 J 剪枝之后、guide 计算之前，提交索引的非终止 child 数，不含 root、终端或 greedy 补全内部候选；`N_mergeable = mergeable_children`：严格同键已有代表 J 不高于该 child 的数量，不含更低 J 的代表替换。分母为零时按没有已观察机会处理，不能通过。

**仅当四项 D0 有效，且至少一例满足 `N_mergeable >= 100` 和 `R_s >= 0.05`，才运行 F30。**

门槛只是工程筛选。大量终端生成、末端展开集中、hash 相同、同坐标到达或较低熵均不能代替这个精确计数。shadow 查询有开销但不实施合并，因此原搜索分支仍按原规则扩展；实际机会数量和时间变化如实记录。

达到固定索引容量后不新增键，未登记状态继续原搜索。记录容量拒绝和 peak payload，不能把容量拒绝当作可剪枝事件。若本轮 D0 未通过，不自动增大容量、改用近似时间／权重、换实例或重复试跑直至通过。

## 3. F30 配对口径

对每个实例和方法，从三次运行按 `(J, repetition)` 排序，取中位代表运行。Pd 取同一条代表路线的值，不能另挑最优 Pd。完整三次结果、范围和失败均保留。

对候选 A 与对照 B 定义：

\[
G_s(A,B)=\frac{\widetilde J_B(s)-\widetilde J_A(s)}{\widetilde J_B(s)},
\qquad
\Delta P_{d,s}=P_{d,A}(s)-P_{d,B}(s).
\]

四个配对分别为 C0_M/C0、C1_M/C1、C1_M/C0_M、C1_M/C0。不得只挑其中一个有利对比代替其余比较。

每个配对的通过条件完全相同：

1. F30 全部 48 项有效。
2. 至少 3/4 实例满足 `G >= 0.005`。
3. Lake 和 Hudson 均至少一个实例满足上述改善门槛。
4. 所有实例 `G >= -1e-8`，相对容差仅排除数值噪声。
5. 所有实例 `ΔPd >= -0.005`，即终点发现概率不损失超过 0.5 个百分点。

这些是开发阶段投入门槛，不是总体显著性、泛化、新颖性或最优性证明。三次重复是计时重复，四个实例已被研究者查看。

## 4. 各结论必须分开

| 观察结果 | 可以支持的解释 | 后续行动 |
| --- | --- | --- |
| D0 未通过 | 本配置和容量下未观察到足够精确等价机会 | 停止，不启动 F30 |
| D0 通过，F30 无质量门槛通过 | 有等价冗余，但本实现未转化为足够收益 | 保存负结果，停止本配置 |
| 只有 C0_M/C0 通过 | 状态合并对一次性求解有用 | 作为通用求解优化候选，不记为滚动增益 |
| C1_M/C1 通过，但 C1_M/C0_M 未通过 | 改善了旧滚动实现，尚未证明净滚动收益 | 不升级第二项滚动贡献 |
| C1_M/C0 通过，但 C1_M/C0_M 未通过 | 完整组合优于旧方法，收益可能主要来自合并 | 保留归因限制，不跳过主要比较 |
| C1_M/C0_M 与 C1_M/C0 均通过 | 同预算下存在净滚动增益，且优于原强对照 | 冻结实现，设计新的独立验证 |
| J 条件通过但 Pd 超门槛下降 | 存在目标权衡 | 单列权衡，停止推广 |
| 阶段有效性失败 | 尚无可比较结果 | 保留故障，修复后新版本、新目录、新冻结 |

本轮将“继续作为滚动创新候选”限定为主要比较 C1_M/C0_M 和组合比较 C1_M/C0 同时通过。不得用内存降低、展开数减少、state 命中率提高替代路线质量门槛。

## 5. 时间、内存与理论解释

所有方法的整次任务预算均为 30 s。C1/C1_M 是五个名义 6 s 槽，计算期间继续执行原承诺前缀，候选接纳必须满足原阶段／总截止和接续时刻。迟到和无改善回退保留。

索引 key 构建、查找、更新、陈旧项判断和内部审计必须计费。`lookup_s` 包含 `key_build_s`，不得重复计时。16,384 条和 64 MiB 是索引约束，不是整体 RSS 上限；原进程限制继续生效。

严格支配证明说明某条等价较差前缀不可能优于保留代表，**不保证有限墙钟下的最终 incumbent 单调改善**。不同的搜索顺序、补全触发次数和索引开销均可能改变定时结果。更低 J 状态必须能够重新进入搜索，旧条目只能在已知更低 J 时跳过。

本轮不登记同质量达标时间的加速结论。平台不等于最优；未实现或未证明的下界不得写成 gap 证书。
