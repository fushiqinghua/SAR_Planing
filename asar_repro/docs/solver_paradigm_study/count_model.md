# 累计命中次数标尺：模型、范围与本地验收

状态：**设计与实现已准备；本轮未执行求解、枚举或测试。** 本文件对应
`src/asar_repro/count_oracle.py`。运行次序与预算以本批主协议为准。

## 1. 目的与约束

本模块用于判断小中规模实例上已有路线距离最优还有多远。它保留固定粒子
轨迹、身份与权重、四邻接、无等待、固定起点、自由终点、完整时域、t=0
不探测、探测后未发现质量不归一化，以及特殊 bins 中的质量。

它不是旧 `exact_repair` 的重命名：位置×生存质量的 McCormick 递推被替换
为完整时域单位流与累计命中次数的整数割线。也不能称“首次全局 MILP”：
旧 API 已允许开放前缀及走廊，既有 toy 也已求过完整模型。

首版仅支持 `ParticleMotion` 与 **标量 0<q<1**。q=0、q=1、非均匀 q 明确
拒绝，不悄悄替换为近似值。正式诊断使用 q=0.78。

## 2. 等价模型

在时间展开图建立弧 `(t-1,u) -> (t,v)`，仅当 v 是 u 的四邻格，且该层可以
从原起点到达。弧变量 f 为二元；起点发出一个单位流，所有内部节点守恒。
终点在最后一层自由选择。不存在等待弧，不固定历史前缀或 incumbent 走廊。

位置变量可以隐含在入流中：

\[
x_{t,v}=\sum_{u:(t-1,u)\to(t,v)}f_{t,u,v}.
\]

对每条粒子轨迹 i，设 r=1-q，初始权重 p_i：

\[
n_{i,t}=n_{i,t-1}+x_{t,c_i(t)},\quad n_{i,0}=0,
\qquad J=\sum_{i,t}p_i r^{n_{i,t}}.
\]

特殊 bin 没有搜索者入流，所以新增命中为零。n 在 MILP 中可设为连续变量：
二元单位流使每个完整整数路线的 n 自动取整数。

引入 z，并加入所有相邻整数点割线：

\[
z_{i,t}\ge r^k[1-q(n_{i,t}-k)],\qquad k=0,\ldots,t-1.
\]

最小化 `sum(p_i*z_it)`。在每个整数 n，所有割线均不超过 r^n，且至少一条
取等号，因此整数最优目标与原 J 完全相同。在两个相邻整数之间，这些线
可能高于光滑指数，**不能将其称为对整个实数域的下切线**。

首版一次加入全部割，便于审查；未实现 lazy separation 或宣称其收益。
约束数量中割线项为 N*T*(T+1)/2，位置单位流只保留真正可达的时间节点。

## 3. 数值证据与预算

`formulation_integer_equivalent=true` 是数学表述的性质，
`formal_certificate=false` 始终保留。SciPy/HiGHS 的 dual 是浮点数值证据，
不是经过区间算术验证的正式证书。

- `presolve=false` 为默认值，保留历史求解器数值问题的防护设置。
- 向 HiGHS 请求 `threads=1`；SciPy 可能报告该选项未在其公开列表中并转交
  后端，完整 warning 会保存。`native_thread_readback_verified=false` 表明未
  伪造原生线程读回证据；本地还须设置主协议的数值库线程环境。
- 不删除或舍入微小割系数；记录最小非零系数和小于 1e-9 的数量。较长时域
  的微小系数要求更加谨慎地解释数值最优性。
- 每条整数候选必须经原 `score_path` 完整复算，逐粒子核对累计命中次数与
  z 的 epigraph 条件。求解器目标低估原 J、reported objective 与 primal 点
  目标不一致、dual 高于已验证可行值超出容差、或已知可行路线下报告
  infeasible/unbounded，均标记 fatal，停止后续正式实验。未收敛可行解的 z
  可以高于精确生存值；这种正 slack 仅记录，路线始终使用原评分器的 J。
- 总预算包含输入校验、初始路线评分、建模、求解和候选审计；求解前预留
  少量审计时间。超时完成的候选保存在 `candidate`，不更新正式 J。
- `solver_lower_bound_raw` 仅供诊断；只有在总预算内完成数值审计时才填写
  `lower_bound`。超时和资源阻塞不冒充最优或零收益。
- `optimal_numeric` 要求求解器状态、候选复算和绝对 gap 同时满足；若正的
  mip_rel_gap 允许提前停止，则可能只返回 `gap_tolerance_reached`。

默认资源门槛为 64 粒子、24 步、100 格、50000 变量、100000 约束及1000000
个估计非零项。真实500粒子场景默认被阻止；本批不因此进行无限扩模。

## 4. 固定诊断实例

`diagnostic_cases('tiny')` 和 `diagnostic_cases('medium')` 各返回9例。
每例包含完整对象和纯JSON `metadata`，后者记录全部轨迹、权重、起点、T、q
及共同初始路线，便于预先冻结。没有根据运行结果选择或调参。

| 家族 | 要检验的机制 | tiny | medium |
|---|---|---|---|
| order | 多区域访问顺序与缓慢移动导致的到达时刻差异 | 4×4，T=4/5/6 | 7×7，T=12/14/16 |
| transfer | 低收益过渡与近处小质量、远处大质量的选择 | 同上 | 同上 |
| repeat | 重复探测与转移，包含不可搜索质量 | 同上 | 同上 |

每例4条带权轨迹。它们是结构诊断题，不代表真实档案的粒子数或统计分布。
共同初始路线是固定合法往返路线，各求解器接收同一条。tiny 可以交给现有
独立 DFS 完整枚举；medium 可能在预算内无法闭合 gap，必须如实标记。

**小实例的最优值不能作为原始500粒子场景的下界。** 改变 T、网格或粒子
集合后得到的是另一道问题；本模块不作这种跨实例证书推断。

## 5. 本地验收要点

先执行本批 runbook 中的测试命令，至少检查：静态与移动目标对独立 DFS
的目标一致；特殊 bins 质量不消失；资源阻塞不调用 MILP；timeout 不报最优；
已验证可行路径与 solver infeasible 冲突时 fatal。测试文件已准备，尚未执行。

tiny 的所有正式记录还应另存独立 DFS 解、枚举完成标志和两者误差，不能
仅根据 MILP 自身状态认定正确。若前置验收失败，保留错误与环境，不开始真实
场景比较，也不事后放宽容差以宣布通过。
