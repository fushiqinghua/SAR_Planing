# 延迟分堆 P30 复核

## 冻结与有效性

实现提交为 `5b0011159fc606e27b080a20b3babd7622dad547`，冻结基点为 `e98908ca6bc2db771a5c43d986446cdbc59f1b86`。协议 SHA-256 为 `01000fad7fa3a3ef4c2f00fe1f43d9b1cf1e926bfc0055c202c6b06a78e8552e`。冻结种子分别为正式 2026112805、消融 2026112806、C0/C0 2026112807。

使用四份原 H2 粒子归档和各自 S30 初始路线。三组共享原八邻接物理模型、forcing、评分器和目标，状态合并关闭。原始路径使用原模型与独立模型双重重放。44 项专项测试、1,841 项全量测试及 29 项子测试通过。8 次轨迹消融、24 次消融计时、12 次 C0/C0、36 次 P30 全部有效，逐次指纹和 J/Pd 算术通过独立复核。36 次 P30 均以 `max_seconds` 停止。

## 正式对照

| 实例 | C0 J | 现有进展 J | 延迟分堆 J | 延迟分堆的 Pd |
| --- | ---: | ---: | ---: | ---: |
| Lake 3101 | 14.307066617 | 14.281396295 | 14.281396295 | 94.7451% |
| Lake 3201 | 14.058508572 | 13.907239443 | 13.907239443 | 93.5634% |
| Hudson 4101 | 28.448979882 | 28.448979882 | 28.448979882 | 81.2461% |
| Hudson 4201 | 58.739707200 | 58.522087200 | 58.522087200 | 9.0948% |

- 4101 的延迟分堆三次均在约 5.95 秒停止额外统计，三次迁移数均为 0。三次最终 J/Pd 与同批 C0 及同批现有进展调度一致，原 J 不退化和 Pd 降幅护栏均通过。上一批现有进展调度的退化在本批未复现。结果说明延迟方案满足当前保护要求，无法单独把恢复归因于延迟分堆。
- 4201 的延迟分堆三次均追平 J=58.5220872、Pd=9.0948%。每次只拆堆一次，记录的迁移耗时为 0.133–0.139 毫秒。该实例峰值 RSS 中位数为 411.9 MiB，同批现有进展调度为 422.6 MiB，C0 为 92.0 MiB。
- 延迟分堆和现有进展调度均相对 C0 通过已见开发实例的主筛选。延迟分堆在四例的代表 J/Pd 与现有进展调度一致，未观察到额外质量收益。计时和内存均按本批记录报告。
